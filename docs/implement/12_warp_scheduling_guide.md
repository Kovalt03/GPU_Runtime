# 12 — 워프 수준 스케줄링 구현 보고서

스켈레톤이 서 있는 상태에서 무엇을 어떤 순서로 채우는지, 각 결정의 트레이드오프가
무엇인지 적는다. 초기 설계 기록 가 "무엇을 왜" 라면 이 문서는 "어떻게" 다.

---

## 참여 마스크 — 도중에 바뀐 설계

**처음 셋을 만들 때는 참여 집합을 `warp.active_mask` 에서 추론했다.** 지금은
`imm` 에 실린 마스크로 **선언**받는다. 넷 다 그렇다.

```cpp
make_s_ballot(dst, src0, participants)
make_s_any(dst, src0, participants)
make_s_all(dst, src0, participants)
make_s_syncwarp(participants)
make_v_shuffle_f32(dst, src0, src1, participants)
```

**왜 바꿨나.** `Independent` 로 넘어가면 "지금 여기 있는 레인" 이 스케줄러의
답이지 프로그램의 답이 아니다. 같은 커널이 같은 입력으로 다른 집합을 대상으로
ballot 할 수 있고, 비교할 정답이 없어진다.

CUDA 가 같은 이유로 같은 길을 갔다. Volta 이전에는 워프가 lockstep 이라
`__ballot` / `__shfl` 에 마스크가 없었고, warp-synchronous 코드가 모델이 약속한
적 없는 수렴에 기대고 있었다. Volta 가 스레드별 pc 를 주면서 — 우리가 `[m1]` 로
방금 한 것이 그것이다 — 마스크 없는 것들이 폐기되고 `_sync` 계열이 들어왔다.
NVIDIA 가 `__activemask()` 를 참여 집합으로 쓰지 말라고 하는 것도 같은 말이다:
**누가 있는지 읽는 것과 누가 있어야 하는지 말하는 것은 다르다.**

**기본값을 두지 않았다.** CUDA 는 `__syncwarp()` 를 `0xffffffff` 로 기본값을
주는데, 그것이 집합을 틀리는 가장 흔한 경로다 — 발산한 커널이 없는 레인을
부른다. 여기서는 호출부마다 쓴다.

**선언했는데 없는 레인은 오류다.** CUDA 는 미정의로 둔다. 여기서는
`require_participants_present` 가 "선언 0x…, 도착 0x…, 누락 0x…" 로 말한다.
마스크는 프로그램에 대한 약속이고, 지킬 수 없는 약속은 조용히 작아진 리덕션보다
메시지로서 값이 크다.

`imm` 에 싣는 방식은 `V_CMP_F32` 가 `CmpOp` 를 나르는 것과 같다 —
`encode_lane_mask` / `decode_lane_mask` 가 `encode_cmp_op` 옆에 있다.

## 1. `S_BALLOT` / `S_ANY` / `S_ALL`

### 어디에 구현하나 — `step_warp()` 가로채기

**`execute()` 의 레인 루프가 아니다.** 거기는 스레드 하나를 인자로 받는데 ballot
은 32 레인을 한꺼번에 봐야 한다. `BARRIER` 와 같은 자리 — `step_warp()` 이
`warp.active_mask` 를 다 만든 **뒤**, 레인 루프에 들어가기 **전**이다.

```cpp
// step_warp(), 지금 BARRIER 를 가로채는 곳 바로 옆
if (program[warp.pc].op == Opcode::BARRIER) { ... }
```

레인 루프의 `case Opcode::S_BALLOT:` 들은 **지우지 말고** "여기까지 왔으면 버그"
라는 throw 로 남긴다. `BARRIER` 가 정확히 그렇게 되어 있다.

### 의미

```
S_BALLOT   masks[dst] = reg[src0] != 0 인 "참여자" 들의 비트
S_ANY      모든 참여자의 reg[dst] = (masks[src0] != 0) ? 1 : 0
S_ALL      모든 참여자의 reg[dst] = (masks[src0] == participants) ? 1 : 0
```

**`S_ALL` 의 비교 대상이 `0xFFFFFFFF` 도 `active_mask` 도 아니다.** 전자는 발산
중에 언제나 거짓이 되고, 후자는 스케줄러의 답이라 `Independent` 에서 비결정적이다.

### `S_SYNCWARP` 만으로는 부족했다

처음에는 "`Independent` 가 참여 집합을 비결정적으로 만들고 `S_SYNCWARP` 이 그것을
고친다" 고 적었다. **반만 맞다.** sync 는 프로그래머가 ballot **앞에 넣어 줘야**
고친다. 그 "넣어 줬겠지" 가 정확히 Volta 가 깨뜨린 warp-synchronous 가정이다.

CUDA 가 `__syncwarp` 만이 아니라 `__ballot_sync` / `__shfl_sync` **전부**에
마스크를 붙인 이유다 — 동기화를 별도 명령어에 맡기지 않고, 각 연산이 참여자를
직접 들게 했다. 그래서 여기서도 넷 다 마스크를 받는다.

### 비용

`gpurt/isa.cpp` 의 비용표에 지금 1 로 두고 "잴 때까지 미정" 이라고 적어 놨다. ballot 은
32 레인을 읽어 접는 것이라 한 레인-op 이 아니다. **재고 나서 고친다.** 지금
그럴듯한 숫자를 넣으면 아무도 안 잰 값이 `RESULTS.md` 에 들어간다.

### 무엇을 재나

초기 설계 기록 가 말한 대로 **워프 내 reduction 두 가지를 비교한다** — 공유 메모리를
쓰는 것과 `S_SHUFFLE`(`V_SHUFFLE_F32`) 을 쓰는 것. 지금 비용 모델로도 유의미하다:
공유 로드 8 대 레지스터 교환 1~2.

## 2. `select_independent_pc()`

### 공정성의 단위가 "레인" 이 아니라 "서로 다른 살아있는 pc" 다

한 pc 의 레인들은 어차피 같이 발행된다. 레인마다 차례를 주면 그 pc 에 몇 레인이
붙었느냐로 가중치가 생겨서 **혼자 기다리는 레인이 똑같이 굶는다.** 교착 재현
테스트가 정확히 1 대 31 이므로 이걸 틀리면 테스트가 안 통과한다.

### 라운드로빈 — 스켈레톤이 이 형태로 서 있다

```
상태:  Warp::last_issued_pc      ← 이미 있다

고르기:
  살아있는 pc 들 중 last_issued_pc 보다 "엄격히 큰" 것 중 최솟값
  없으면 전체 최솟값으로 되돌아간다 (순환)
  고른 값을 last_issued_pc 에 저장하고 반환
```

`select_independent_pc()` 에 레인 루프와 `successor` / `smallest` 두 변수까지
서 있다. 채울 것은 **루프 몸통 한 조각과 마지막 두 줄**이다.

**상태를 `Warp` 에 둔 이유가 테스트 하나를 만든다.** 스케줄러는 워프들을 번갈아
도므로, 커서를 스케줄러에 두면 다른 워프의 차례가 이 워프의 커서를 밀어 버린다.
**워프 하나로는 안 잡힌다** — 번갈아 돌 상대가 없으면 공유 커서와 전용 커서가
똑같이 행동한다. `DISABLED_IndependentSchedulingIsFairWithinEachWarpSeparately`
가 워프 둘로 그걸 잡는다.

"pc 집합이 분기로 바뀌어서 기억한 값이 더는 없을 수 있다" 를 걱정거리로 적었던
것은 **틀렸다.** "보다 큰 것 중 최솟값" 은 기억한 값이 집합에 없어도 잘 정의된다.
스켈레톤 주석은 고쳐 놨다.

### 나이 기반과의 비교

스레드마다 "마지막으로 발행한 뒤 지난 턴" 카운터를 두고 가장 오래된 것을 고른다.
상태가 32 배 들고 스텝마다 갱신해야 한다. 라운드로빈이 이 교착을 푸는 데 충분하고
더 싸므로, **나이 기반은 라운드로빈이 못 푸는 사례가 나오면** 그때 간다.

### 비용

`min_pc` 를 찾는 루프가 이미 32 레인을 돈다. 라운드로빈도 같은 한 바퀴로 되므로
**스텝당 비용은 안 늘어난다.**

## 3. `S_SYNCWARP` — 완료

**`BARRIER` 에서 복사해 오면 안 되는 것이 셋이었다.**

`warp.at_barrier = true; return false;` 가 첫째다. 그 플래그는 **블록 배리어
전용**이고, `release_barrier()` 가 큐가 마를 때까지 워프를 잡아 둔다. 그러면
워프 안을 맞추는 명령어가 **블록 전체를 기다리게** 된다. 빼고 `return true` 로
바꿔도 결과가 동일했다 — 아무것도 벌지 않고 워프 간 결합만 만들고 있었다.

`instruction_cost(Opcode::BARRIER)` 가 둘째. 지금 둘 다 1 이라 수치가 같지만,
비용을 재서 고치는 순간 조용히 어긋난다.

"Past the barrier before waiting" 주석이 셋째. 여기서 pc 를 올리는 것은 전원이
도착해서 **통과**하기 때문이지 대기 전에 미리 지나가는 것이 아니다.

**앞질러 간 레인은 판정한다.** 참여자로 선언됐는데 살아 있으면서 pc 가 sync 보다
크면 영영 안 온다. 예산이 닳을 때까지 기다리는 대신 그 레인 번호를 지목한다 —
`BARRIER` 가 "32 개 중 16 개만 도달" 이라고 말하는 것과 같은 결이고, CUDA 가
미정의로 두는 자리다.

**대기 턴은 `warp_steps` 만 센다.** 아무 레인도 일을 안 했으므로 `active_lane_ops`
는 안 올린다. 그러면 그 스텝이 `divergence_rate` 에 낭비로 잡히는데, 그것이 대기의
비용이므로 맞다.

## 4. `V_SHUFFLE_F32`

### 이 명령어가 하는 일

**레인이 다른 레인의 레지스터를 읽는다.** 이 ISA 에서 값이 메모리를 거치지 않고
레인 사이를 건너는 유일한 길이다.

```
lane i:  reg[dst] = (reg[src1] 이 가리키는 레인).reg[src0]
```

`src1` 은 값이 아니라 **레인 번호**를 들고 있고, 그 번호가 레인마다 다르다.
그래서 한 명령어가 워프 전체의 gather 가 된다.

```
          src0 값        src1 (읽어올 레인)      dst 결과
lane 0      10                 1                   20
lane 1      20                 2                   30
lane 2      30                 0                   10      ← 회전
```

**무엇에 쓰나.** 지금 워프 안에서 32 개를 더하려면 공유 메모리를 거쳐야 한다 —
`V_ST_SHARED_F32` → `BARRIER` → `V_LD_SHARED_F32`. 로드 하나가 8 이고 배리어는
가장 느린 워프를 기다린다. shuffle 은 레지스터에서 끝난다:

```
step 1  lane i 가 lane i+16 을 읽어 더한다     살아있는 값 32 → 16
step 2  lane i 가 lane i+8  을 읽어 더한다              16 → 8
step 3  ... i+4                                          8 → 4
step 4  ... i+2                                          4 → 2
step 5  ... i+1                                          2 → 1   lane 0 에 합
```

다섯 스텝. **`[m2]` 의 숫자가 나오는 자리가 여기다** — 같은 reduction 을 공유
메모리로 한 것과 재서 비교한다. 초기 설계 기록 가 "공유 로드 8 대 레지스터 교환 1~2"
라고 적어 둔 그 비교다.

### 스켈레톤이 서 있다

enum·이름·비용·팩토리가 들어갔고 (`OPCODE_COUNT` 30), `step_warp()` 가로채기에
피연산자 검증·참여자 검증·`require_lane_index` 까지 서 있다. **남은 것은 교환
자체 한 덩어리.**

`-Wswitch` 가 `opcode_name()` 과 `execute()` 의 누락을 컴파일 타임에 잡아 줬다 —
opcode 를 추가할 때마다 그렇다.

### 왜 `S_` 가 아닌가

레인마다 **다른** 값을 받으므로 워프 균일이 아니다. `gpurt/isa.hpp` 의 "S\_ 가 여기서
무엇을 뜻하는가" 절이 그 경계를 적어 놨고, `OpcodeNamesFollowScheme` 이 기계로
검증한다.

### 함정 — 읽기를 다 끝내고 쓰기 시작해야 한다

```
잘못:  레인마다 (src 레인에서 읽어서 → 자기 dst 에 쓰기) 를 순서대로
       → 레인 0 이 쓴 값을 레인 1 이 원본으로 읽는다

맞게:  32 레인의 src0 을 먼저 전부 읽어 임시에 담고, 그 다음에 쓴다
```

한 칸 밀기로 보면 분명하다. `dst == src0` 이고 lane i 가 lane i+1 을 읽는다면:

```
시작        [10, 20, 30, ...]
순서대로    lane 0 이 lane 1 을 읽어 자기에 쓴다 → [20, 20, 30, ...]
            lane 1 이 lane 2 를 읽는다            → [20, 30, 30, ...]
            ...  결과가 한 칸 밀린 것이 아니라 뭉개진다

먼저 읽고   [20, 30, 10, ...]  ← 의도한 회전
```

`V_NORM_VEC3_F32` 같은 기존 벡터 연산에는 없던 문제다. 그것들은 레인 안에서만
움직인다.

### 레인 인덱스가 float 이다

`src1` 이 가리키는 레지스터에 레인 번호가 float 으로 들어 있다. `require_lane_index`
가 정수인지, `[0, 32)` 안인지 본다 — 이미 써 뒀다.

**참여자 밖 레인에서 읽으면 어떻게 할지는 정해야 한다.** CUDA 는 미정의다. 여기서는
`require_participants_present` 가 이미 "없는 레인을 부르면 거부" 하므로, 같은 결로
거부하는 편이 일관된다. `dst` 를 안 건드리는 쪽도 되지만 말해 주는 것이 적다.

### 마스크도 받는다

셋과 같은 규약이다. `make_v_shuffle_f32(dst, src0, src1, participants)`.

## 5. reduction 벤치마크 — 완료

`[m2]` 를 결론으로 닫고 비용 다섯을 측정치로 바꾼다.

```
(A) 공유 메모리   V_ST_SHARED → BARRIER → V_LD_SHARED,  log2(32) = 5 회
(B) shuffle       V_SHUFFLE_F32 + V_ADD_F32,            5 회
```

**결과: 68 대 33.** 다섯 라운드는 같고 라운드 하나가 다르다.

**순서를 지킨 것이 값을 했다.** shuffle 비용을 1 로 둔 채 weighted 로 재면 (B) 가
이기는 것이 당연해진다 — 재는 것이 아니라 가정을 확인하는 것이 된다. 그래서
비용표가 안 건드리는 것(명령어 수, 발행 스텝)을 세고, weighting 은 **뒤집어서**
"shuffle 이 얼마나 비싸야 두 경로가 같아지나" 를 물었다. 답이 22 이고, 가격을 8 로
바꾼 뒤에도 22 그대로다 — 명령어 구성에서 나온 수라 가격에 안 흔들린다.

**배리어에 대한 예측은 틀렸다.** "가장 느린 워프를 기다리는 정지가 `warp_steps` 에
나타난다" 고 적었는데 안 나타난다. 워프 수에 정확히 비례한다. 이 기계는 배리어
정지에 아무것도 안 물리고, 그것이 하드웨어에서는 배리어 비용의 대부분이다.
그래서 이 비교는 공유 메모리를 실제보다 유리하게 잡고 있다.

각 커밋을 **clean 빌드**로 확인한다 (`--clean-first`). 증분 빌드가 옛 바이너리를
남겨 거짓 통과를 만든 적이 있다 — `ctest` 는 빌드하지 않는다.
