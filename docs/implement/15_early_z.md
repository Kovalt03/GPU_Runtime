# 15 — `[e]` early-Z 구현 보고서
> 초기 설계 기록 의 마지막 파이프라인 항목. 두 단계로 갔다 — 먼저 래스터에 조명을
> 달고(그게 없으면 잴 것이 없다), 그 위에 depth prepass 를 얹었다.

## 1단계 — 래스터가 자기가 그린 것을 밝힌다

**왜 먼저였나.** early-Z 는 셰이딩을 건너뛰는 최적화다. 무게중심 색은 곱셈 여덟
번이라, 그걸로 재면 "졌다" 는 나오지만 **어느 지점에서 이기기 시작하는지**를 말할
수 없다.

**가능해진 이유가 `[b]` 다.** `gpurt/pipeline/raytrace.hpp` 에 이렇게 적혀 있었다 — "Barycentric
은 래스터가 낼 수 있는 유일한 것이다. 패스 1 이 화면 x·y·깊이·1/w 만 남기므로
빛이 필요한 월드 위치와 법선은 패스 2 가 돌 때 이미 없다." 지오메트리가 장치에
남게 되면서 **월드 정점이 그대로 있다.**

```
점 P   = 패스 1 이 읽은 월드 정점 셋을, 색과 같은 perspective 보정 가중치로 보간
법선 N = 삼각형당 하나, 호스트가 cross(v1-v0, v2-v0) 정규화해서 업로드
결과   = base × max(0, dot(N, normalize(light - P)))
```

법선을 커널에서 유도하지 않고 읽는 이유: 레이 트레이서는 이미 들고 있는 엣지로
cross 를 하면 되지만, 래스터는 그걸 하려고 월드 정점 셋을 또 읽어야 한다. 호스트가
한 번 계산한 것을 로드 하나로 가져오는 편이 싸다.

**검증이 진짜다.** 두 렌더러가 **같은 조명 프레임**에 도달한다 — 레이 트레이서는
광선-삼각형 교차로 P 를 풀고, 래스터는 투영된 삼각형 위에서 보간한다. 서로 다른
경로로 같은 그림이 나오는 것이 둘 다 맞다는 뜻이다 (1% 미만 픽셀 차이, PIXEL_EPS).

**한계는 범위로 적었다.** 조명은 **walk 전용**이다. 타일드 경로는 타일 목록에서
삼각형을 읽는데 그 목록은 화면 좌표만 담는다. 밝히려면 목록이 정점당 월드 위치와
삼각형당 법선만큼 커져야 하고, 그건 커널이 아니라 비닝 포맷의 변경이다. 조용히
안 밝힌 프레임을 주는 대신 **던진다.**

## 2단계 — depth prepass

```
DepthUse { None, Prepass, EarlyZ }   커널 빌더 하나, 런치 둘
draw_early_z(rt, geometry, frame, target, shading)
```

prepass 는 걷되 색을 안 쓰고 픽셀당 최소 깊이만 저장한다. 본 패스는 그 깊이를
**루프 앞에서 한 번** 읽고, `depth <= visible_z` 인 삼각형만 셰이딩한다. 두 패스
사이에 sync 를 안 넣으므로 카운터는 **둘의 합**이다 — walk 한 번과 비교하는 것이
이 트레이드의 질문이니까.

`<=` 를 쓴 이유: prepass 가 같은 명령을 같은 순서로 돌리므로 승자의 값은 비트까지
같지만, `==` 는 그 사실에 기대는 것이고 `<=` 는 안 기댄다.

## 나온 것

뒤에서 앞으로 쌓은 전면 삼각형 — walk 의 최악이자 prepass 의 최선이다. 모든
삼각형이 모든 픽셀을 덮고 매번 더 가까우므로 walk 은 전부 셰이딩한다.

| 씬 | 깊이 복잡도 | flat | coalesced | cached | 사이클 |
|---|---:|---:|---:|---:|---:|
| 무게중심 | 4 | +96.9% | +80.4% | +75.2% | +91.6% |
| 무게중심 | 32 | +98.4% | +81.6% | +71.9% | +82.8% |
| 조명 | 4 | +36.9% | +39.8% | +33.8% | +52.4% |
| 조명 | 32 | **+29.9%** | +30.3% | **+20.5%** | +32.1% |

**프레임은 픽셀 단위로 같다** (EQ). 값은 전부 진다.

### 놀란 지점 — 깊이 복잡도가 결정하지 않는다

early-Z 가 이용하라고 있는 바로 그것인데, 8 을 넘으면 수치가 안 움직인다. 지오메트리를
두 배로 하면 **양쪽이 같이 두 배**가 된다.

### 결정하는 것은 비율이다

`c` = 삼각형 하나의 커버리지 비용, `s` = 셰이드 하나의 비용이라 하면

```
walk      = Nc + Ns          (뒤→앞이므로 전부 셰이딩)
early-Z   = 2Nc + s          (커버리지 두 번, 셰이드 한 번)
비율      → 2 / (1 + s/c)
```

두 모드가 정확히 `c` 와 `s` 를 한 번씩 재준다. 깊이 32 무게중심이 `Nc` =
83,000,320 이고, 같은 씬에 조명을 켜면 44,895,872 가 붙는다 →
**c = 2,593,760, s = 1,402,996, s/c = 0.54.**

| | 예측 2/(1+s/c) | 실측 |
|---|---:|---:|
| 무게중심 | 1.980 | 1.984 |
| 조명 | 1.298 | 1.299 |

**교차점은 이 셰이더의 1.85 배.** `s/c > 1` 이 조건이고, normalize 하나짜리 diffuse
점광원은 그 절반을 조금 넘는다. 텍스처 페치와 그림자 항이 붙은 셰이더면 넘는다 —
직감이 아니라 **반증 가능한 숫자**다.

### 나머지 절반은 `c` 쪽에 있다

prepass 가 되풀이하는 것이 `c` 고, 타일드 경로는 이미 그걸 깎아뒀다 — 비닝이 픽셀이
볼 일 없는 삼각형을 버린다. 그런데 타일드는 아직 밝힐 수 없다. **이 측정의 흥미로운
판본은 비닝 포맷을 키운 뒤에야 나온다.**

## 검증

- `ctest` **275/275** (Debug 전체 약 30초, `-j4` 로 11초)
- **프레임 동일** — early-Z 와 walk 이 두 셰이딩 모드 모두에서 픽셀 단위로 같다 (EQ)
- **두 렌더러가 조명 프레임에서 일치** — 서로 다른 방법으로 같은 P 에 도달한다
- **깊이 버퍼 직접 확인** — prepass 가 쓴 값이 뷰 볼륨 안이고, 덮이지 않은 픽셀은
  커널이 시작한 2.0 을 그대로 들고 있다
- **거부** — 타일드/공유에 Diffuse, 법선 없는 지오메트리에 조명
