# 27 — `[g2]` TLAS 구현 보고서
> **4단계의 둘째.** `[i]` 가 준 "인스턴스 = 변환 + 참조" 를 레이 트레이서로 가져왔다.
>
> **결과 한 줄**: TLAS 는 **속도가 아니라 메모리의 답**이다. 256 복사본에서 메모리
> 12.5배 이기고 작업량 0.59배 진다. 그리고 지는 이유가 `[i]` 를 틀리게 만든 것과
> **같은 없는 명령어**다.

## 인스턴스 레코드가 19 float 인 이유

```
[0..15]  world → object
[16]     이 인스턴스의 하위 트리가 시작하는 바이트 오프셋
[17]     삼각형이 시작하는 오프셋
[18]     재질
```

**16, 17 이 "복사밭" 을 "장면" 으로 바꾼다.** 처음엔 하위 트리 주소가 커널에 상수로
구워져 있었다 — 그래서 큐브 100 개는 표현되고 **큐브 옆의 구는 안 됐다.** 리프에서
이미 16 로드를 내고 있으므로 둘이 더 붙는 값은 로드 2 개다.

**18 은 런타임이 절대 해석하지 않는다.** 프래그먼트 셰이더에 도달하고 거기서 멈춘다.
그게 요점이다 — 워프의 레인을 갈라놓는 것이 **재려고 만든 키가 아니라 장면 자체**여야
하고, 그것이 `[m7]` 이 기다리던 입력이다. 래스터 경로에서는 0 이다 (래스터라이저는
물체가 아니라 삼각형을 그리므로 픽셀이 어디서 왔는지 모른다).

## 기하를 옮기지 않고 레이를 옮긴다

인스턴스마다 삼각형을 변환하면 트리도 인스턴스마다다. 대신 **레이를 인스턴스 공간으로**
보내면 트리 하나가 전부를 섬긴다. 비용은 MATVEC 둘.

**`t` 가 그대로 살아남는 것이 이 수법의 핵심이다.** 방향을 벡터로(w=0) 옮기고
**정규화하지 않으면**, 객체 공간의 `t` 가 곧 월드의 `t` 다. 그래서 `best_t` 가
인스턴스를 가로질러 그냥 비교된다 — 되돌릴 필요가 없다.

```
TLAS 순회 (월드 레이)
  └ 리프 → 인스턴스마다
        레이를 M⁻¹ 로 옮긴다 (MATVEC 둘)
        BLAS 순회 (객체 레이)   ← [g1] 의 루프 그대로
              └ 리프 → 삼각형
```

## 잡은 버그 — 레인 슬라이스

```cpp
stack_slot = lane * (a.stack_depth * sizeof(float));   // 틀림
```

공유 메모리 슬라이스를 **아래 층 깊이로만** 잡아놓고 BLAS 스택을 위층 너머로 밀었다.
레인 0 의 BLAS 스택이 **레인 1 의 TLAS 스택을 덮어썼다.** 인스턴스가 통째로 사라졌고,
프레임은 여전히 프레임처럼 보였다 (lit 63 → 43).

고침은 한 줄이다 — 슬라이스가 **둘의 합**이어야 한다. 위층은 아래층을 걷는 동안에도
스택에 남아 있으니까. `run_raytrace_stage` 의 용량 검사도 합으로 고쳤다.

**잡아낸 것은 픽셀 단위 대조뿐이다.** 스택 깊이를 8 씩 늘려봐도 안 고쳐졌다는 것이
용량이 아니라 배치 문제라는 신호였다.

## 겹친 인스턴스에서는 마지막 비트까지 안 맞는다

기준(호스트에서 펼친 기하 + 단일 트리)과 대조했더니 **커버리지는 항상 정확히 같은데
색이 몇 픽셀 다르다.** 원인:

- 기준은 **정점**을 M 으로 옮기고, TLAS 는 **레이**를 float 로 계산한 M⁻¹ 로 옮긴다
- 깊이가 서로 한 ulp 안에 있는 두 면에서 승자가 뒤집힌다

**커버리지가 안 움직이는 것이 주장이고**, 그게 스택 버그가 깨뜨렸던 바로 그것이다.
그래서 테스트를 둘로 갈랐다:

| 테스트 | 씬 | 주장 |
|---|---|---|
| `TwoLevelsDrawWhatOneLevelOverFlattenedCopiesDoes` | 인스턴스가 안 겹침 | 색까지 일치 |
| `OverlappingInstancesAgreeOnCoverageAndNotAlwaysOnDepth` | 겹침 | **커버리지 정확히 일치**, 깊이 무승부는 유계 |

`[i]` 의 결합법칙 발견(`DOC/26`)과 같은 종류다 — 수학적으로 같은 두 경로가 부동소수에서
갈리고, **무엇이 어긋나도 되고 무엇이 안 되는지**를 테스트가 나눠 말한다.

역시 벌어지면서.

### 같은 없는 명령어가 두 번째로 지목됐다

인스턴스 하나를 방문할 때 **역행렬 16 스칼라 로드 × 100 = 1,600** 을 순회 시작 전에 낸다.
`V_LD_CONST_MAT4_F32` 옆에 비어 있는 **`V_LD_GLOBAL_MAT4_F32`** 이면 2 접근이다.

`DOC/26` 도 같은 부재를 지목했는데, **둘 다 틀렸다.** 만들어서 재보니 Flat 에서는
아무것도 안 움직인다 — 와이드 로드는 레인당 과금 아래에서 정확히 자기 부품들이고,
사는 것은 라인 수라 `Coalesced` 만 본다 (`DOC/26` 참조). 이 표의 작업량은 명령어를
기다리던 것이 아니라 **레인당 과금 아래의 2단 순회 비용**이다.

**상수 창은 여기서 못 쓴다 — 배관이 아니라 과금 때문이다.** 같은 TLAS 리프에 있는 두
레인이 서로 다른 인스턴스일 수 있어서 주소가 워프 유니폼이 아니다. `[i]` 는 블록을
인스턴스 하나에 묶어서 쓸 수 있었지만, 레이 트레이서는 못 묶는다.

## 거부하는 것

**점광원.** 확산항은 월드 공간 법선을 요구하는데 인스턴스의 엣지는 자기 공간에 있다.
넘겨오려면 **역전치**가 필요하고, 안 만들었다. 회전한 인스턴스를 **거의 맞게** 칠하는
대신 거부한다. Barycentric 과 Custom 은 `u, v, t` 만 쓰고 셋 다 보존되므로 그대로 된다.

## 레지스터가 세 번째로 바닥났다

2단 커널이 250 에서 터졌다. `IRBuilder::Scratch` 를 넣었다 — 범위 안에서 할당한 것을
되돌려주는 RAII. 범프 할당기에 수명 분석이 없어서 슬랩 테스트 임시값이 프로그램 끝까지
자리를 잡고 있었다.

**위험한 도구다.** 범위 안에서 만든 값을 밖에서 읽으면 조용히 깨진다. 그래서 계약을
헤더에 크게 적고, **범위 밖에 선언된 레지스터에 써 넣고 끝나는 계산**(슬랩 테스트,
행렬 적재)에만 썼다.
