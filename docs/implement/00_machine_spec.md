# 00 — 가상 기계 명세

> **이 문서가 시뮬레이션 대상의 정의다.** 다른 모든 문서는 이것을 구현하거나,
> 이것과의 차이를 말한다.
>
> 번호가 `00`인 이유: 나머지가 이 위에 선다. 실제로는 `01`~`12`를 다 쓴 뒤에
> 적었고, 그 순서가 뒤집혀 있었다는 것이 이 문서가 존재하는 이유다.

## 왜 뒤늦게 쓰는가

기계 모델은 처음부터 있었다. 적혀 있지 않았을 뿐이다. `WARP_SIZE`,
`instruction_cost`, min-PC 재수렴 — 전부 코드에 흩어져 있었고, 각각은 그럴듯한데
**어디에도 "우리 기계는 이렇다"가 없었다.**

그래서 새 질문이 나올 때마다 논증을 처음부터 다시 세웠다:

- coalescing 을 재려는데 메모리 시스템이 정의돼 있지 않다 → `DOC/09` 에서 보류
- 정점 캐시가 있는가? → `[9c]`/`[9d]` 가 반사실 지표가 되어 떠다님
- `V_LD_GLOBAL_VEC3_F32` 은 몇 트랜잭션인가? → 답할 근거 없음
- GIOPS 는 무엇을 재는가? → 알고 보니 Debug 빌드의 속도

**이 문서 이후로 그런 질문은 논증이 아니라 조회다.** 답이 여기 없으면 그건
"아직 정하지 않았다"이고, 그것도 하나의 답이다.

## 1. 실행 모델

| | |
|---|---|
| 워프 크기 | **32 레인**, 고정 |
| PC | **스레드마다 하나.** `Thread::pc` 가 유일한 진실이다 |
| 워프 상태 | `Warp::pc` 와 `activeMask` 는 저장된 상태가 아니라 **매 스텝 계산 결과** |
| 스케줄링 정책 | **min-PC.** 살아있는 스레드의 PC 중 최솟값을 고르고 거기 있는 레인만 참여 |
| 재수렴 | **저절로.** PC 가 다시 같아지면 다시 모인다. 스택도 post-dominator 분석도 없다 |

**Volta 쪽이지 Volta 이전이 아니다.** 갈리는 선은 스레드가 자기 PC 를 갖느냐다.

```
Volta 이전   워프에 PC 하나 + reconvergence 스택.
             (마스크, 재합류 지점) 을 쌓고 한쪽을 끝까지 돌린 뒤 다른 쪽.
             스레드가 독립적으로 나아갈 수 없다.

Volta ITS    스레드마다 PC 와 호출 스택. 스케줄러가 같은 지점의 스레드를 묶는다.
             자동 재수렴이 없어 __syncwarp() 를 컴파일러가 넣는다.

우리         스레드마다 PC ✔ 스택 없음 ✔ — 여기까지 Volta.
             다만 정책이 "항상 최솟값" 이라 재수렴이 공짜로 따라온다.
```

`DOC/04` 가 이 결정을 기록하고 있다. 초안은 `BRA_DIV` 에서 PC 갱신과 마스킹을
겹쳐 쓰다가 "언제 다시 켜지는가" 가 정의되지 않았고, PC 를 유일한 진실로 두는
쪽으로 바꾸면서 재수렴이 부수 효과가 됐다. 역방향 분기(루프)도 그냥 되는 것이
같은 이유다 — 되돌아간 스레드가 PC 가 작으니 먼저 돌고, 빠져나오면 만난다.

### 실제 Volta 와 갈리는 곳 — forward progress

**min-PC 는 Volta 의 전진 보장을 주지 않는다.** 낮은 PC 의 스레드가 언제나 먼저
돌기 때문이다.

```
스레드 A 가 pc=5 에서 B 가 쓸 값을 기다리며 회전하고,
스레드 B 는 pc=20 에 있다.

  Volta    스케줄러가 B 를 돌릴 수 있다 → 진행한다
  우리     min_pc 가 5 에 붙박이고 A 만 영원히 돈다 → 교착
```

**Volta 가 ITS 를 도입해 고친 것이 정확히 이 SIMT-induced deadlock 인데, 우리는
자료 구조만 가져오고 그 보장은 안 가져왔다.** 워프 안 producer-consumer 를 쓸 수
없다는 뜻이고, 이 시뮬레이터 위에서 그런 커널을 쓰면 멈춘다.

고치려면 스케줄링 정책을 바꿔야 한다 — 최솟값 고정 대신 라운드로빈이나 나이
기반으로. 자료 구조는 이미 그것을 받을 수 있다. → `DOC/11`

## 2. 레지스터 파일

| | |
|---|---|
| 스레드당 | **256** 개, `float` |
| 정수 레지스터 | **없다** |
| 예약 | `r250`~`r252` 블록 좌표, `r253`~`r255` 전역 스레드 좌표 |
| 초과 | 런치가 **예외를 던진다.** 자르거나 회전하지 않는다 |

**정수 레지스터가 없다는 것이 파급이 크다.** 주소는 float 으로 계산되고,
`V_LD_GLOBAL_F32` 는 `global[reg[src0] + imm]` 를 읽는다. 인덱스 버퍼도 float
으로 올라간다 — 정수는 2²⁴ 까지 정확하므로 정점 1,600 만 개까지 안전하다.

비교 결과도 float 이다. `V_CMP_F32` 가 1.0 / 0.0 을 쓰고, 그래서 `min` 이 AND,
`max` 가 OR 이 되며 `BRA_DIV` 와 조합된다. 프리디케이션이 새 opcode 없이 되는
것도 이 성질 덕이다.

## 3. 메모리

| 공간 | 크기 | 비고 |
|---|---|---|
| 전역 (device) | 런타임 생성자가 정함 | 호스트와 **별개 주소 공간** |
| 공유 (block) | **4096 float** = 16 KB | 블록당 |
| 상수 | **없다** | 유니폼은 명령어에 구워진다 |
| 로컬 / 스필 | **없다** | 레지스터가 모자라면 예외 |

할당은 free list, 정렬 **16 바이트**. 아레나는 자라지 않는다 — 실제 GPU 의 VRAM
이 고정이고, 늘리면 `bytes` 가 재할당되어 나눠준 포인터가 전부 매달린다.

### 비용 모델은 셋이고, 기본값은 옛 것이다

`MemoryModel` 이 전역 접근의 값을 정한다. 기본값 `Flat` 이 아래 §4 의 고정
비용이고, 나머지 둘은 **켜야 켜진다** — 그래서 예전 측정치가 안 흔들린다.

| | 무엇을 세나 |
|---|---|
| `Flat` | 레인마다 `instruction_cost`. 주소 패턴을 못 본다 |
| `Coalesced` | 워프의 주소들이 걸치는 **고유 128 바이트 라인** 수 |
| `Cached` | 그 라인이 L1(1024) / L2(65,536) 에 있었는지까지. LRU, 태그만 |

`LatencyModel::Modelled` 은 여기에 시간을 붙인다 — L1 30, L2 200, 메모리 400,
그리고 스코어보드가 없어 워프가 발행 후 결과를 기다린다.

**따라온 것.** `V_LD_GLOBAL_VEC3_F32` 이 이 자 위에서 값을 갖게 되어 구현됐다
(레이 트레이서 트랜잭션 -24.7%, 사이클 -42.9%, `Flat` 은 무변화). 공유 메모리
staging 이 "100 대 8 산수" 로만 설명되던 것은 재보니 **이득 자체가 아니었다.**

### 여전히 명시적으로 없는 것

**대역폭이 없다.** 트랜잭션을 세기만 하고 줄 세우지 않는다 — 공유 자원도, DRAM
행 버퍼도, 천장도 없다.

**용량 미스가 안 난다.** `draw_*` 가 호출마다 할당하고 해제하지 않아서 모든
미스가 compulsory 다. 초기 설계 기록 의 `[b]`.

**AoS vs SoA 를 아직 안 쟀다.** 이제 잴 수는 있다.

## 4. 명령어 비용

`weighted_lane_ops = Σ (활성 레인 수 × instruction_cost(op))`.

| 비용 | 명령어 | 근거 |
|---:|---|---|
| **1** | `V_MUL/ADD/SUB/FMA/MIN/MAX/MOV/CMP_F32` | FP32 ALU 한 번. 기준 단위 |
| **1** | `BRA`, `BRA_DIV`, `RET` | 발행 자체. 발산 비용은 워프 스텝이 늘어 나타난다 |
| **1** | `BARRIER` | 실제 비용은 **기다림**인데, 발행된 일만 세는 모델에는 안 보인다 |
| **3** | `V_ADD/SUB/SCALE/DOT_VEC3_F32` | 스칼라 3 회. 벡터 유닛이 따로 있는 게 아니다 |
| **4** | `V_RCP_F32`, `V_SQRT_F32` | SFU — 개수가 적고 파이프가 깊다 |
| **9** | `V_CROSS_VEC3_F32` | 곱 6 + 뺄셈 3 |
| **12** | `V_NORM_VEC3_F32` | dot 3 + rsqrt 4 + scale 3, 어림 |
| **16** | `V_MATVEC_MAT4_F32` | 4×4 FMA |
| **8** | `V_LD/ST_SHARED_F32` | 온칩. 수백이 아니라 수십 사이클 |
| **100** | `V_LD/ST_GLOBAL_F32` | 오프칩 |

### 이 숫자들의 지위

**측정된 값이 아니다.** 어떤 실제 GPU 에서 뽑은 것이 아니라, **비율이 그럴듯하도록
정한 값**이다. 실제 하드웨어에서 대략:

```
FP32 FMA        throughput 1 사이클
SFU (rsqrt 등)  throughput 약 4 배 느림
공유 메모리     지연 수십 사이클
전역 메모리     지연 200~400 사이클
```

`1 : 4 : 8 : 100` 이 그 모양을 따른다. **절대값이 아니라 비율이 주장의 근거다** —
"공유 메모리가 95% 아꼈다" 는 100 과 8 의 비에서 나오지 100 이 맞아서가 아니다.

그리고 이 표는 **throughput 모델이지 latency 모델이 아니다.** 전역 로드가 100
인 것은 "100 사이클 기다린다" 가 아니라 "ALU 명령 100 개만큼의 발행 자원을
먹는다" 로 읽어야 한다. 진짜 지연과 그것을 숨기는 일은 §6 에 없다.

## 5. 고정 기능 블록 — **하나도 없다**

| 블록 | 우리 |
|---|---|
| Input Assembler + post-transform vertex cache | **없음** |
| 래스터라이저 (edge function, quad 생성) | **없음** — 커널이 한다 |
| Hi-Z / Early-Z | **없음** |
| ROP (블렌딩, depth write) | **없음** |
| 텍스처 유닛 / 샘플러 | **없음** |
| BVH 순회 / RT 코어 | **없음** |
| 클리핑 | **없음** |

**이 기계는 그래픽스 ASIC 이 아니라 SIMT 머신이다.** 렌더링은 전부 커널로
표현된다 — Larrabee, CUDA 소프트웨어 래스터화, Nanite 의 compute 경로와 같은
자리다.

의도된 선택이다. 고정 기능 래스터라이저를 시뮬레이션했다면 **워프라는 개념이
없는 곳**이 되고, 발산을 잴 것이 없어진다.

### 5.1 Input Assembler 가 없다는 것의 값

`[9]` 가 답을 남긴 자리다.

정점 스테이지가 고유 정점을 화면 버퍼에 **materialise** 하고 인덱스로 되읽는다.
정점당 변환 **정확히 1 회**, 삼각형 순서와 무관하다. 고정 기능 IA 는 대신 32
엔트리 FIFO 를 두고 밀려난 정점을 재변환하므로 순서가 곧 비용이다.

측정 (구, 정점 182 / 삼각형 360):

```
32 엔트리 FIFO 였다면, 뒤섞인 순서   삼각형당 2.54 변환
32 엔트리 FIFO 였다면, Forsyth 정렬   삼각형당 0.64
우리 (materialise)                    삼각형당 0.51
```

**materialise 가 산 것은 5 배**다. 대가는 정점 V 개짜리 화면 버퍼와 런치 하나.

그래서 `optimised_for_cache()` 는 여기서 **아무것도 벌지 않는다** —
`weighted_lane_ops` 가 0.004% 움직이고 그 잔차마저 정점 캐시가 아니라 깊이
순서에서 온다. 같은 ACMR 을 갖는 두 순서(가까운 것부터 / 먼 것부터)가 divergence
1.23% 와 3.07% 로 갈린다.

## 6. 스케줄링

| | |
|---|---|
| 워프 선택 | 라운드로빈 |
| 블록 | **순차 실행.** 한 블록이 끝나야 다음이 시작한다 |
| SM | **하나.** 여러 개가 아니다 |
| occupancy | **개념이 없다** |
| latency hiding | **없다** |
| 스트림 / 비동기 | **없다.** 모든 런치가 동기 |

**워프를 32 개씩 묶는 진짜 이유가 이 모델에는 없다.** 실제 GPU 는 한 워프가
메모리를 기다리는 동안 다른 워프를 발행해 ALU 를 놀리지 않는다. 여기서는
명령어 비용이 고정 숫자 하나라 "기다린다" 를 표현할 곳이 없다.

`DOC/11` 의 `[c]` 이고, 그 항목이 큰 이유이기도 하다 — 고치려면 명령어에
latency 와 throughput 을 나눠 주고, 워프마다 스코어보드를 두고, 상주 워프 수를
런타임이 정하게 해야 한다.

### 배리어

`BARRIER` 는 블록의 **모든** 스레드가 도달해야 통과한다. 발산 상태로 도달하면
**거부한다** — 실제 CUDA 는 미정의 동작으로 두지만, 조용히 틀리는 것보다 낫다.

스케줄러는 준비 큐가 비는 것을 도착 신호로 쓴다. → `DOC/10`

## 7. 런치 모델

```
myrt_launch(kernel, grid, block, args)
```

`dim3` 3 차원, `grid` 는 블록 수, `block` 은 블록당 스레드 수. 블록당 스레드는
워프 크기로 올림되고, 남는 레인은 비활성으로 시작한다.

**커널 함수는 런치당 한 번 호출된다.** `Program` 을 만들어 돌려주고, 그 프로그램을
블록의 모든 스레드가 공유한다. 스레드마다 다른 것은 §2 의 예약 레지스터에 심긴
좌표뿐이다.

그래서 호스트가 아는 값은 전부 명령어에 구울 수 있다 — 카메라 행렬, 해상도,
버퍼 오프셋. 상수 메모리가 없어도 되는 이유이고, `V_MATMUL_MAT4_F32` 를 만들지
않은 이유이기도 하다.

## 8. 통계 — 무엇이 재현되고 무엇이 아닌가

| 카운터 | 뜻 | 재현 |
|---|---|---|
| `warp_steps` | 워프에 발행된 명령어 수 | **예** |
| `active_lane_ops` | 실제로 실행된 레인-명령어 | **예** |
| `weighted_lane_ops` | 위를 `instruction_cost` 로 가중 | **예** |
| `divergence_rate` | 발행된 레인 슬롯 중 마스킹된 비율 | **예** |
| `throughput_giops` | 시뮬레이터가 호스트에서 도는 속도 | **아니오** |

**앞의 넷은 이 명세의 함수다.** 기계·빌드 타입과 무관하게 같은 값이 나온다.
Debug 와 Release 에서 바이트 단위로 같다는 것을 확인했다.

**마지막 하나는 이 명세와 무관하다.** 호스트 CPU 가 시뮬레이터를 얼마나 빨리
씹느냐이고, 최적화 여부에 4 배 가까이 좌우된다. 한동안 이 값이 Debug 빌드의
속도를 재고 있었다.

### `divergence_rate` 가 못 보는 것

발행된 슬롯만 센다. **가중하지 않으므로** 비싼 명령어를 싸게 만들어도 안 움직이고,
균일한 일을 없애면 오히려 올라간다. 타일 비닝이 작업을 85% 줄이면서 divergence 를
0.4% → 2.1% 로 올린 것이 그 예다.

지표 하나로 튜닝하면 안 된다는 실례이고, `RESULTS.md` 가 그 절을 갖고 있는
이유다.

## 8.5 무엇을 세고 무엇을 실행하나

이 기계는 **기능적으로 정확하고 시간적으로는 세는** 기계다. 값은 언제나 맞다 —
`DeviceSpan` 이 유일한 원본이고 모든 로드가 거기서 읽는다. 비용은 그 옆에서
따로 센다.

그래서 **값이 달라지지 않는 것은 구현하지 않고 센다.** coalescing 은 32 개 요청을
실제로 합치지 않고 라인 수만 센다 — 합쳐도 같은 값이 나오므로 관찰 가능한 차이가
비용뿐이다. 캐시도 태그와 LRU 순서만 두고 데이터 배열을 두지 않는다.

**값이 달라지는 것은 구현한다.** `V_SHUFFLE_F32` 는 값이 레인 사이를 실제로
건너므로 진짜로 옮긴다. `BARRIER` 는 실행 순서를 실제로 바꾼다.

이 선이 §9 가 "답하지 않는다" 고 적은 것들의 경계이기도 하다. 대역폭 포화나
트랜잭션 경합은 시간의 문제이므로 셀 수는 있지만, 세려면 **공유 자원을
모델링해야** 하고 그것은 사이클 정확 시뮬레이터의 일이다.

## 9. 이 명세가 답하지 않는 것

의도적으로 비워둔 자리다. 각각 `DOC/11` 에 항목이 있다.

| | 왜 |
|---|---|
| 캐시 라인 크기, coalescing 규칙 | `[d]`. 실행 모델을 건드려야 하고 측정치가 전부 다시 나온다 |
| 명령어 지연, 상주 워프 수 | `[c]`. 스케줄러의 실행 모델을 바꾸는 일 |
| depth 버퍼, early-Z | `[e]` |
| BVH, 순회 유닛 | `[g]` |
| 텍스처, 블렌딩, 클리핑 | 하지 않는다 |

**여기 없는 것을 구현할 때는 먼저 이 문서에 한 줄을 더한다.** 코드가 명세보다
앞서 나가면 이 문서를 쓰게 만든 그 상태로 돌아간다.

## 10. 지향점 — 어느 세대를 목표로 하는가

**가능한 한 현대 GPU 다.** 옛 모델을 정확히 재현하는 것은 목표가 아니다.

**Volta 가 최신은 아니다.** 2017 년이고 그 뒤로 Turing·Ampere·Hopper·Ada·
Blackwell 이 있다. Volta 를 기준으로 삼은 것은 **실행 모델이 거기서 갈렸기
때문**이다 — 스레드별 PC 냐 reconvergence 스택이냐. 그 선 이후로 실행 모델
자체는 크게 안 바뀌었고, 바뀐 것은 그 위에 얹힌 것들이다.

이미 현대 쪽인 것:

| | 세대 |
|---|---|
| 스레드별 PC, 스택 없는 재수렴 | Volta 2017 |
| 인덱스 버퍼를 materialise 하는 정점 스테이지 | **Turing 2018** mesh shader 계열 |
| compute 로 하는 래스터화 | Nanite 2021 계열 |

아직 아닌 것, 그리고 그것이 "옛날" 인지 "빠진 기초" 인지:

| | 성격 | 계획 |
|---|---|---|
| 전진 보장 (ITS) | **옛날** — Volta 가 고친 것 | `[m1]` |
| warp-level primitives | **옛날** — Kepler 2012 부터 있다 | `[m2]` |
| 비동기 런치 / 스트림 | **옛날** — 처음부터 있던 것 | `[m4]` |
| 비동기 복사 (`cp.async`) | **옛날** — Ampere 2020 | `[m5]` |
| 텐서 / 행렬 유닛 | **옛날** — Volta 2017 | `[m6]` |
| SER — 발산 재정렬 | **옛날** — Ada 2022 | `[m7]` |
| thread block cluster | **옛날** — Hopper 2022 | `[m8]` |
| latency hiding, occupancy | **빠진 기초** — 2006 년 이후 전부 | `[m3]` |
| coalescing, 캐시 계층 | **빠진 기초** — 마찬가지 | `[d]` |

**아래 둘은 세대 문제가 아니다.** GPU 라는 것이 처음부터 갖고 있던 성질이고,
없는 것은 그냥 구멍이다. 위의 다섯은 "언제 생겼는가" 를 말할 수 있는 것들이다.

순서와 이유는 초기 설계 기록 §두 갈래에 있다. 요지는 `[m3]` 이 `[m4]`·`[m5]` 의 선행
조건이라는 것 — 기다림이 모델에 없으면 비동기가 겹칠 것이 없다.
